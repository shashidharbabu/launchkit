# Spline live-embed integration

Everything needed to put a `.splinecode` scene on a Next.js 14 App Router page
without wrecking it. Verified against `@splinetool/react-spline` 4.1.0 +
`@splinetool/runtime` 1.12.98.

## The cost, in numbers (measured Aug 2026)

- `@splinetool/runtime` `build/runtime.js`: 2,049,196 bytes raw / **581,897
  bytes gzipped** from unpkg.
- Plus the scene: `.splinecode` payloads commonly run 0.5–5MB depending on
  geometry/textures, streamed from `prod.spline.design` (third-party origin —
  add `<link rel="preconnect" href="https://prod.spline.design" />` if
  embedding eagerly).
- Plus WebGL context creation and first-frame render on the main thread.

Consequences: if the scene mounts eagerly in the hero, your LCP is whenever
the canvas paints — seconds on mid-range Android. Every pattern below exists
to keep LCP on a poster image instead.

## Baseline: deferred client-only embed with poster

```tsx
// components/spline-scene.tsx
'use client';
import dynamic from 'next/dynamic';
import Image from 'next/image';
import { useEffect, useState } from 'react';

const Spline = dynamic(() => import('@splinetool/react-spline'), { ssr: false });

const SCENE = 'https://prod.spline.design/XXXX/scene.splinecode';

export function SplineHero({ className }: { className?: string }) {
  const [enabled, setEnabled] = useState(false);
  const [loaded, setLoaded] = useState(false);

  useEffect(() => {
    const reduced = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
    const smallScreen = window.matchMedia('(max-width: 1023px)').matches;
    const saveData = (navigator as any).connection?.saveData === true;
    if (!reduced && !smallScreen && !saveData) setEnabled(true);
  }, []);

  return (
    <div className={className} aria-hidden="true">
      <Image
        src="/spline/hero-poster.webp" alt="" fill priority
        className={`object-cover transition-opacity duration-700 ${loaded ? 'opacity-0' : 'opacity-100'}`}
      />
      {enabled && (
        <Spline scene={SCENE} onLoad={() => setLoaded(true)}
                className="absolute inset-0" />
      )}
    </div>
  );
}
```

- The poster is the LCP element: `priority`, exported from Spline as a
  high-res image (Hobby+ for high-res, watermark-free).
- Reduced-motion, mobile, and Save-Data users never download the runtime.
- `onLoad` cross-fades poster → canvas; no black-rectangle flash.
- `aria-hidden` on the wrapper because this variant is decorative.

### `@splinetool/react-spline/next`

The `/next` entry (hence the `next >= 14.2.0` peer dep) can render an
autogenerated **blurred placeholder on the server** — export the scene as
"Next.js" in the Spline editor to generate it:

```tsx
import Spline from '@splinetool/react-spline/next';
<Spline scene="https://prod.spline.design/XXXX/scene.splinecode" />
```

Good for eager, interactive-is-the-product embeds. It does NOT remove the
runtime cost on the client, and the blur placeholder is not a substitute for
the reduced-motion/mobile gating above — keep the wrapper component.

## Lazy-mount below the fold

Same gating, but keyed on visibility with framer-motion's `useInView`
(`once: true, margin: '400px'`) so the 582KB chunk downloads only when the
user approaches the section. Combine with the poster pattern — visibility
switches `enabled`, not the render of the poster.

## Pointer events: canvas behind hero copy

The classic bug: a full-bleed Spline canvas sits behind the headline and CTA,
and either (a) the canvas eats clicks meant for the CTA, or (b) you
`pointer-events-none` the canvas and lose scene interactivity.

```tsx
<section className="relative isolate min-h-[80vh] overflow-hidden">
  {/* decorative: never interactive */}
  <SplineHero className="pointer-events-none absolute inset-0 -z-10" />
  <div className="relative z-10 mx-auto max-w-2xl px-6 py-32">
    <h1>…</h1>
    <a href="/signup" className="…">Start free</a>
  </div>
</section>
```

If the scene must stay interactive (drag-to-orbit), invert it: canvas keeps
pointer events, and the copy block gets `pointer-events-none` with
`pointer-events-auto` restored on each link/button. Also add
`touch-action: pan-y` styling on the canvas wrapper so vertical scroll is
never hijacked on touch devices. Never leave scroll-zoom enabled on a scene
embedded in a scrolling page — disable zoom events in the Spline editor.

## Driving the scene from React (runtime API)

From the react-spline README (v4):

```tsx
import type { Application, SPEObject } from '@splinetool/runtime';

function onLoad(spline: Application) {
  const cube: SPEObject | undefined = spline.findObjectByName('Cube');
  spline.setZoom(1);
  cube?.emitEvent('mouseHover');          // trigger scene events from app state
  spline.setVariable('price', 49);        // scene variables (Pro feature in editor)
}
<Spline scene={SCENE} onLoad={onLoad}
        onSplineMouseDown={(e) => { if (e.target.name === 'Cube') … }} />
```

Available event props follow the pattern `onSplineMouseDown`,
`onSplineMouseHover`, `onSplineKeyDown`, etc. `renderOnDemand` prop (default
true) keeps the runtime from re-rendering frames when nothing changes — leave
it on.

## Alternatives to the live embed

| Export (from Spline editor) | Plan | Integration |
|---|---|---|
| Image (PNG/WebP) | Free (watermark) / Hobby+ (clean, hi-res) | `next/image`, done. 99% of "3D hero" requests actually want this |
| Video (MP4/WebM loop) | Pro | The `jitter` skill's background-video pattern applies verbatim (`autoPlay muted loop playsInline poster` + `motion-reduce:hidden`) |
| Live embed iframe (`my.spline.design/...`) | Free (watermark) | Avoid: iframe still loads the full runtime, adds a nested browsing context, and you lose the poster/gating control above |
| Self-hosted `.splinecode` + code export | **Enterprise** (per Aug 2026 pricing) | Only path that removes the `prod.spline.design` dependency; the README's "download the file to fix CORS" tip assumes you're licensed for it |

## Checklist before shipping a live embed

- [ ] Poster image exported, `priority`-loaded, cross-fade wired.
- [ ] Runtime gated: reduced motion, <1024px, Save-Data all get the poster.
- [ ] Decorative → `aria-hidden` + `pointer-events-none`; interactive →
      copy stacked above with pointer-events restored on controls.
- [ ] No watermark visible (plan ≥ Hobby for exports, ≥ Pro for embeds).
- [ ] `preconnect` to `prod.spline.design` if eager.
- [ ] Scroll not hijacked on touch; scene zoom disabled in editor.
- [ ] Bundle check: runtime chunk is route-local and lazy, never in shared
      layout JS. `next build` — the 582KB gz should appear as an async chunk.
- [ ] Someone owns the Spline file and its URL (document it in the repo).

## Anti-patterns

- Runtime in the hero of a page whose job is conversion + Core Web Vitals.
- `import Spline from '@splinetool/react-spline'` in a Server Component
  (crashes) or statically in a shared layout (582KB gz for every route).
- Decorative canvas without `pointer-events-none` — ghost click-blocker.
- Mounting the runtime for reduced-motion users and merely pausing animation
  — they paid the download for nothing; don't mount at all.
- Two Spline scenes live on one page.
- Assuming self-hosting `.splinecode` is fine on a $12 plan — it's listed
  under Enterprise; verify before architecting around it.
